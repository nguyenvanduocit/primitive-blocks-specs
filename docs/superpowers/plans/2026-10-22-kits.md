# Kits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the `kit` concept to the library: a kit format, a validator, the first kit `kits/app-factory/` (guides, manifest, tools), an entry skill `skills/implement-kit.md`, and kit pages on the docs site.

**Architecture:** A kit is a folder whose `README.md` frontmatter is the manifest. Pure Node modules in `docs/` parse and validate manifests and render kit page bodies; `docs/build.mjs` wraps those bodies in the existing site chrome. Tools are standalone Python scripts with a `--dry-run`. Guides are generalised from a source playbook the owner provides at build time.

**Tech Stack:** Node 26 (`node:test`, no dependencies, no package.json), Python 3.12 (stdlib `unittest`; Pillow and fontTools for the compose tool), Markdown.

**Spec:** `docs/superpowers/specs/2026-10-22-kits-design.md`

## Global Constraints

- Language of all kit content: English.
- The source project is never named. No product name, no absolute home paths (`/Users/`, `~/projects`), no emails, no account, team or app identifiers, no credentials in any committed file. The source location is `<SOURCE_DIR>`, a path the owner supplies at build time; it is never written into a committed file.
- Every observed duration or count in a guide carries the words "observed once, on one project" in the same file.
- Guides reference blocks by id and never copy block content.
- A kit never lists another kit. Kit id equals its folder name (`app-factory`).
- Tools read secrets only from environment variables, declare them in the manifest (`requires_env`), exit with code 2 and name the variable when it is missing, and have `--dry-run` that never calls a service.
- No new npm or pip dependencies beyond Pillow and fontTools for the compose tool.
- No git commands until the owner asks. Before any git command, and before any run of `node docs/build.mjs`, message the parallel session found through `ListAgents` that also edits this repo. `docs/build.mjs`, `docs/index.html` and `docs/blocks/*` are shared with it.
- Blocks live under `blocks/<category>/<slug>/`; kits under `kits/<id>/`; a block id `category.slug` maps to `blocks/<category>/<slug>/README.md`. Do not edit block content. The only edits to existing blocks, `README.md`, `skills/implement-block.md` and `docs/build.mjs` for the move are path references (Task 0).
- The site follows the existing visual style; no decorative metadata (no fake document numbers, sheet labels, revision numbers, or padding paragraphs).

## Review Focus

1. Manifest names a block id, guide file or tool file that does not exist: `validateKit` returns an error for each (Task 1).
2. Manifest `name` contains `: ` inside quotes (the app-factory name does): the parser keeps the whole string (Task 1).
3. A guide states durations or counts without the "observed once" wording: content test fails (Task 4).
4. A kit file leaks a local path, email, private key header or an owner-supplied scrub term: scrub test fails (Task 4).
5. A tool is run without its env var, or with a malformed size: exit 2 naming the problem, no traceback (Tasks 2, 3).
6. A kit with no tools or no blocks renders a page without `undefined` or `[object` in it (Task 10).

### Task 1: Manifest parser and validator

**Files:**
- Create: `docs/kit-manifest.mjs`, `docs/kit-check.mjs`, `docs/kit-manifest.test.mjs`

**Interfaces:**
- Produces:
  - `parseFrontmatter(md: string): object`. Reads the leading `---` block. Supported subset: `key: value` scalars (quoted or bare; `true`/`false` become booleans, everything else stays a string), inline lists `[a, b]`, block lists of scalars (`- x`), block lists of maps (`- key: v` plus following indented `key: v` lines), trailing `# comments` outside quotes. Throws `Error("no frontmatter")` when absent.
  - `loadKit(repoRoot: string, id: string): { id: string, dir: string, meta: object, body: string }`, reading `kits/<id>/README.md`.
  - `validateKit(repoRoot: string, id: string): string[]`, empty when valid. Error strings:
    `guide missing: <file>` · `tool missing: <file>` · `block missing: <id>` · `block id mismatch: <id>` · `unknown block reference: <id>` · `kit lists a kit: <id>`.
    A block id `cat.slug` resolves to `blocks/<cat>/<slug>/README.md` whose frontmatter `id` must equal it. Backticked tokens matching `` `([a-z]+\.[a-z][a-z-]*)` `` in the README and every listed guide whose prefix is a directory directly under `blocks/` must resolve to a block, otherwise `unknown block reference`.
- CLI: `node docs/kit-check.mjs <id>` prints each error on its own line and exits 1, or prints `ok: <id>` and exits 0.

- [ ] **Step 1: Write failing tests in `docs/kit-manifest.test.mjs`** using `node:test` and a `makeFixture()` helper that builds a temp repo (`os.tmpdir`) with one block `blocks/auth/login/README.md` (`id: "auth.login"`) and a kit directory. Tests (names are the contract):
  - `parseFrontmatter parses scalars and inline lists`: `tags: [a, b]` → `["a","b"]`, `complexity: high` → `"high"`.
  - `parseFrontmatter parses a list of maps`: three `blocks` entries each with `id`, `phase`, `when`.
  - `parseFrontmatter keeps a colon inside a quoted string`: `name: "App Factory: idea to paid app"` → exact string.
  - `parseFrontmatter strips trailing comments but not # inside quotes`.
  - `parseFrontmatter throws without frontmatter`.
  - `validateKit reports a missing guide, tool and block` → exactly `["guide missing: guides/x.md","tool missing: tools/t.py","block missing: auth.nope"]` for a fixture that lists those.
  - `validateKit reports an id mismatch` (folder `auth/login` whose README says `id: "auth.other"`).
  - `validateKit reports an unknown block reference` (a guide containing `` `auth.ghost` ``).
  - `validateKit returns [] for a consistent kit`.
- [ ] **Step 2:** Run `node --test docs/kit-manifest.test.mjs`. Expected: FAIL (module not found).
- [ ] **Step 3:** Implement `docs/kit-manifest.mjs` as ES module exporting the three functions; implement `docs/kit-check.mjs` using `loadKit`/`validateKit` with repo root resolved from `import.meta.url`.
- [ ] **Step 4:** Run `node --test docs/kit-manifest.test.mjs`. Expected: all pass.
